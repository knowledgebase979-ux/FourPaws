## 2. מטרת המוצר והדרישות שסוכמו

אפליקציית Web בעברית וב־RTL לניהול הטיפול בכלבים. שם המותג שנבחר: FourPaws. היעד העיקרי הוא טלפון סלולרי, כולל iPhone; נדרשת גם תצוגה תקינה במחשב.

- הרשמה קצרה בשם משתמש וסיסמה, התחברות ומידע אישי נפרד לכל משתמש. אין לשמור סיסמאות גלויות.
- כרטיסים לכמה כלבים: שם, גזע, גודל, משקל, תאריך לידה, הערות, שבב ופרטי מרפאה.
- ספריית מידע שימושי ממקורות וטרינריים מוסמכים, חיפוש וסינון.
- גזעים וסינון לפי גזע, גודל ומשקל; זיהוי חזותי משוער מתמונה.
- יומן בריאות, שקילות ומגמה, תיעוד תסמינים והערות.
- מעקבים ותזכורות, חזרות, תיעוד ביצוע וייצוא ליומן.
- התייעצות AI על סימנים ופצעים, עם תמונה ותיאור, כהכוונה ראשונית בלבד.
- חיפוש Google באמצעות Gemini למידע, מוצרים ומרפאות, עם מקורות והשוואות לפי מחיר או אזור כאשר קיימים נתונים מאומתים.

אין דרישה לבצע רכישות, הזמנות או לשלוח הודעות. אין להוסיף תשלומים, מנויים או רכיבים אחרים ללא צורך.

## 3. החלטת העיצוב העדכנית — עדיין פתוחה

המשתמש דחה במפורש את העיצוב הירוק שהוצג: הוא נראה לו כמו מערכת למחשב, לא יפה ולא עכשווי. לאחר מכן בחר באפשרות ״צבעוני וידידותי״: צבעים חיים, צורות רכות ואווירה קלילה של אפליקציה לחיות.

הקוד בחבילה עדיין מכיל את העיצוב הירוק שנדחה. הוספו לו שיפורי קריאות וניווט, אך העיצוב הצבעוני החדש טרם מומש. אין לתאר את עבודת העיצוב כהושלמה או מאושרת.

יש לבנות תחילה מסך בית לנייד: היררכיה קצרה, טיפוגרפיה ברורה, פעולות גדולות למגע, תוכן שמתאים לרוחב 360–430 פיקסלים, ניווט תחתון וגישה לכל תשעת המסכים. לצמצם טקסט שיווקי, כרטיסים חוזרים ובאנרים שתופסים את המסך. להציג למשתמש תצוגת טלפון אמיתית, ואז להחיל את השפה על ההתחברות, הכרטיסים, היומן, התזכורות, הספרייה וה־AI. אין להסתפק בהקטנת מסך המחשב.

## 4. מה קיים ומה אומת

קיימים תשעה מסכים: dashboard, dogs, breeds, library, tracking, health, vision, consult, find. קיימים 12 פרופילי גזע ו־16 מדריכי ידע. החבילה כוללת שינויים מקומיים שטרם פורסמו.

23 בדיקות Node עברו ב־6.11.2026. npm run build ו־npm run validate עברו. הבדיקות מכסות הרשמה, התחברות, בידוד משתמשים, cookies, CSRF, התמדה בקבצים, מתאם D1 עם SQLite, התנגשויות גרסה, ולידציה, rate limits, רינדור המסכים, טופס admin, ייצוא ICS וחוזה Gemini עם ספק מדומה.

תיקונים מקומיים אחרונים:
- כפתורי עזר בתוך טפסים מוגדרים type="button" כדי שלא ישלחו בטעות טופס.
- נוסף תפריט ״עוד כלים״ בנייד, שמאפשר גישה לכל המסכים.
- חיפוש הספרייה הופרד מסינון הגזעים כדי שלא ישפיעו זה על זה.
- הוחמרה ולידציה למזהי רשומות, תאריכי לידה לא אפשריים, רשומות null ותיעוד בריאות בעתיד. מזהים עוברים escaping גם בהצגה.
- גוף JSON שאינו אובייקט מוחזר כשגיאת 400 במקום 500.
- נוסף newId עם fallback ל־crypto.getRandomValues כאשר crypto.randomUUID אינו זמין בתצוגת HTTP מקומית.
- הורחבה הספרייה מ־7 ל־16 מדריכים וקושרו מקורות שנבדקו.

בדפדפן נבדקו לוח הבית וטופס היומן עם נתוני דוגמה מקומיים. נמצאה שגיאת crypto.randomUUID בתצוגת HTTP; תוקנה ונוספה בדיקת regression. השמירה המלאה בדפדפן לאחר התיקון טרם אומתה. בדיקות מובייל מלאות והעיצוב החדש עדיין חסרים. אין להציג את בדיקות ה־VM כבדיקות דפדפן מלאות.

## 5. מבנה הקוד והרצה

Node.js 22.13 ומעלה. השרת אינו תלוי בחבילות npm חיצוניות. אין צורך במיגרציה ל־React כדי להמשיך.

- public/index.html — מעטפת HTML בעברית וב־RTL.
- public/app.js — כל ממשק המשתמש, המסכים, האינטראקציות, מאגרי הגזעים והמדריכים.
- public/style.css — העיצוב וההתאמות למסכים. כרגע קיימות שכבות CSS מצטברות; לנקות במסגרת העיצוב החדש.
- worker/index.js — API משותף, auth, ולידציה, Gemini, security headers ומתאם D1.
- server.mjs — שרת HTTP מקומי ומתאם FileStore.
- drizzle/0000_pawpath.sql — סכמת D1: users, sessions, states, rate_limits.
- scripts/build.mjs — בניית Worker עם HTML/CSS/JS מוטמעים.
- scripts/validate-artifact.mjs — אימות חבילת Worker.
- tests/app.test.mjs ו־tests/frontend.test.mjs — 23 בדיקות.
- .env.example — שמות הגדרות בלבד; אין מפתח אמיתי.
- .openai/hosting.json — זהות האתר והגדרת binding למסד הנתונים.

פקודות, מתוך שורש הפרויקט:
```bash
node --version
npm test
npm start
```
פתח http://localhost:3000/admin בדפדפן של אותו מחשב. בטלפון localhost מתייחס לטלפון עצמו; יש להשתמש בתצוגה מקדימה שהסביבה מספקת או בכתובת מחשב נגישה, לא להבטיח שקישור localhost יעבוד מהטלפון.

לבנייה ואימות:
```bash
npm run build
npm run validate
```

נתוני ההרצה המקומית נוצרים ב־data/: users.json, sessions.json, records.json, rate-limits.json. הם אינם בחבילה ואינם ב־Git. הקבצים נשמרים בהרשאות מוגבלות; הסיסמאות הן PBKDF2 hashes. ניהול הקבצים מיועד לתהליך Node יחיד. בפריסה המתארחת הנתונים נשמרים ב־D1 ולא בקבצים מקומיים.

## 6. כניסת admin

admin הוא שם המשתמש של אפליקציית FourPaws, לא GitHub ולא Google. אין לחשבון תפקידי ניהול מיוחדים כרגע.

בנתיב /admin קוראים ל־/api/entry. אם אין חשבון admin, המשתמש בוחר סיסמה אישית ומאמת אותה. אם כבר קיים, הוא נכנס עם סיסמתו. אין סיסמת ברירת מחדל; אין לקבוע סיסמה בקוד, לשלוח אותה בצ׳אט או לאפס חשבון קיים ללא הוראה.

נדרשים 10–128 תווים. הטופס כולל הודעות שגיאה מפורשות, מצב טעינה ומניעת שליחה כפולה. בקשות רגילות מוגבלות ל־20 שניות ובקשות AI ל־120 שניות. קיום חשבון admin באתר החי לא אומת מחדש בזמן ההעברה. נתוני QA אינם משתמש אמיתי ואינם נכללים בחבילה.

## 7. חיבורים וסודות — הגישה לא ניתנה אוטומטית

המשתמש אישר שימוש במפתח Gemini בפרויקט ורוצה שלסביבת ההמשך יהיו החיבורים הדרושים. האישור אינו מעביר בפועל סודות או מעניק ל־Codex גישה לחשבונות. לא הועתקו סודות למסמך, לארכיון או ל־Drive.

GEMINI_API_KEY: סוד שרת. הוגדר באתר הקיים באמצעות משתני הסביבה של Sites. המפתח אינו במאגר או בקבצי ההעברה. יש להגדיר אותו בסביבת Codex/השרת בערוץ סודות מאובטח, עם אישור בעל החשבון, בלי להדפיס את ערכו. אין לכלול אותו בקוד לקוח, ב־URL, בלוגים, ב־Google Docs או ב־Git. מפתח שסופק בעבר בצ׳אט מומלץ להחליף; לא בוצעה החלפה או ביטול.

GEMINI_MODEL: ערך תצורה לא סודי. הערך האחרון שהוגדר הוא gemini-3.8-flash. הוא הוחזר ברשימת המודלים בבדיקה הקודמת. יש לבדוק זמינות ותמיכה ב־images, structured outputs ו־google_search בחשבון לפני שינוי. אין להחליף ספק AI ל־OpenAI ללא בקשת המשתמש.

GitHub: החיבור הוא OAuth/אפליקציית GitHub, לא מפתח בתוך FourPaws. חשבון היעד knowledgebase979-ux והמאגר FourPaws. יש לחבר את סביבת Codex בהרשאת כתיבה למאגר הזה. ההרשאה של בעל החשבון אינה מוכיחה שהאינטגרציה עצמה יכולה לכתוב. אין לבקש סיסמת GitHub או token בצ׳אט.

Google Drive: נדרש חיבור מורשה לקריאת תיקיית ההעברה. אין לאפליקציית FourPaws תלות ב־Drive בזמן הרצה; הוא משמש למסמכים וחבילת הקוד. אין צורך ליצור service-account key כדי להריץ את FourPaws. אם לסביבת Codex אין כלי Drive, הורד את הארכיון דרך חשבון המשתמש וצרף אותו לפרויקט.

Sites: נדרשת גישת בעלים כדי לעדכן את האתר הקיים. project_id הוא appgprj_6aee0394632c8191bc3a0be2e20817d7. source credentials זמניים יש להנפיק מחדש דרך השירות ולא לשמור. אין להעביר bypass tokens. אין לשנות audience, למחוק D1 או ליצור אתר כפול. לשלב הנוכחי אין הרשאת פרסום חדשה: עובדים מקומית.

PORT, DATA_DIR ו־PUBLIC_ORIGIN הם הגדרות הרצה ולא סודות. בקובץ .env מקומי שלא נכנס ל־Git ניתן להגדיר סודות באמצעות כלי מאובטח ואז להריץ node --env-file=.env server.mjs. אין להעתיק קובץ .env אל public או dist. יש לבדוק נוכחות סוד בלי להציג את ערכו.

## 8. מצב GitHub והאתר הקיים

המאגר https://github.com/knowledgebase979-ux/FourPaws היה public בבדיקה האחרונה. הענף main מכיל רק Initial commit עם README. ה־SHA שנצפה: f38b2939bf57d7d7c94eaac18fa4d73e75a9779f. יש לקרוא שוב לפני כתיבה, כי המצב עלול להשתנות.

ניסיונות create_tree ו־create_file דרך החיבור הקודם נכשלו ב־403 Resource not accessible by integration. לא הועלה לשם קוד הפרויקט. ניסיון התחברות דרך Google בדפדפן לא השלים הגדרת הרשאות. המשתמש ביקש להימנע מחלונות התחברות מסורבלים; אין לחדש את השרשרת הזו בלי צורך והסכמה.

האתר החי נשמר במאגר מקור מנוהל נפרד של Sites. ה־commit האחרון שנפרס לפני השינויים המקומיים הוא e44f2d006189f51d0e6d1582c1599e93bffd0699. הפריסה המוצלחת האחרונה: appgdep_6aee192af2408191b799a6ba10bf9be6. משתני הסביבה היו revision 1.

האתר פרטי לבעלים ודורש כניסה ל־ChatGPT לפני כניסת FourPaws. לא שונה קהל היעד. GitHub Pages לבדו אינו מריץ את שרת ה־Node, ה־sessions או קריאות Gemini הסודיות של הפרויקט. שינוי פרטיות המאגר ושיתוף האתר הם פעולות נפרדות.

## 9. Gemini: מימוש ומגבלת האימות

השרת משתמש ב־Google generateContent, שולח את המפתח ב־x-goog-api-key, ובחיפוש מפעיל google_search. התייעצות עם תמונה משתמשת ב־inlineData ובסכמת JSON. המקורות והצעות החיפוש של Google מוצגים בממשק. טקסט וקישורים עוברים בדיקה כדי למנוע הפעלת תוכן זר.

הגבלת השימוש: 15 בקשות למשתמש ב־15 דקות. חיפוש מעביר שאלה, עיר והעדפת מיון; אינו שולח את ההערות הרפואיות בכרטיס הכלב. התייעצות עשויה להעביר גזע, משקל, תאריך לידה והערות, ולכן נדרשת הסכמה ברורה. התמונה מוקטנת בדפדפן ואינה נשמרת בשרת או ביומן. מדיניות הנתונים אצל Google תלויה במסלול השירות.

בדיקת רשימת המודלים הצליחה בעבר ב־HTTP 200. ניסיונות יצירת תשובה וחיפוש חי החזירו 429 ו־503. טרם אומתה תשובת Gemini חיה מוצלחת או פענוח תמונה חי. יש לבדוק מכסות, חיוב וזמינות; אין לקבוע שחיוב הוא בוודאות סיבת הכשל. בדיקות היחידה משתמשות בספק מדומה ואינן מוכיחות איכות רפואית או השוואת מחירים אמיתית.

## 10. מידע רפואי וגבולות המוצר

ה־AI נותן מידע ראשוני ותיאור מסויג, לא אבחון. אין לקבוע ש״לא צריך וטרינר״ על סמך תמונה, להבטיח שפצע בטוח, להציע מינונים או לתת טיפול פולשני. הסתייגות כללית אינה מכשירה עצה מסוכנת.

סימני חירום שסומנו מחזירים הפניה למרפאה לפני קריאת AI, גם אם אין מפתח. צילום אינו שולל עומק פצע, זיהום או מחלה מערכתית. יש לשמור בממשק את ההפרדה בין תצפיות, אפשרויות, דחיפות, צעדים, מגבלות ושאלות חסרות. חומרת מקרה אמיתי נקבעת בידי וטרינר.

## 11. מגבלות קיימות שאין להסתיר

אין איפוס סיסמה, MFA או אימות דוא״ל. אין הרשאות מנהל מיוחדות ל־admin. PBKDF2 משתמש ב־100,000 איטרציות בהתאם למימוש Workers הקיים; אין להציג זאת כסקירת אבטחה מלאה.

התראות דפדפן פועלות רק כשהאפליקציה פתוחה. ICS מאפשר תזכורות באמצעות יומן חיצוני, אך אינו מסתנכרן לאחר הייבוא; ייבוא חוזר עלול ליצור כפילויות. אין Push ברקע.

זיהוי גזע משתמש ב־Hugging Face Transformers וב־Xenova/resnet-50 בדפדפן. ההורדה והפענוח לא אומתו מקצה לקצה; זיהוי תערובת גזעים אינו נתמך וציון מודל אינו הסתברות ודאית.

אין GPS או מנוע מרחקים: קרבה בחיפוש מבוססת עיר. מחירים, משלוח, מלאי ושעות פתיחה דורשים אימות; אין מנוע שסורק את כל החנויות. אין צ׳אט רב־שלבי עם זיכרון שיחה.

## 12. סדר העבודה הבא וקריטריוני סיום

1. הורד את חבילת המקור, אמת את manifest.sha256 וקרא את המסמכים. שמור את החבילה המקורית לפני עריכה.
2. פתח את התיקייה כפרויקט מקומי, הרץ npm test, npm run build ו־npm run validate. אל תטען שהאתר החי כולל את השינויים האלה.
3. עצב מחדש קודם לנייד בכיוון צבעוני וידידותי. בדוק 360, 390 ו־430 פיקסלים: ללא גלילה אופקית, ללא טקסט חתוך, שדות לפחות 16px ויעדי מגע נוחים. הצג צילום של הנייד, לא רק מחשב.
4. בדוק בדפדפן הרשמה/כניסת admin, יציאה וכניסה חוזרת, יצירת כלב, שמירת הערה ושקילה, השלמת תזכורת חוזרת, סינון גזעים, חיפוש בספרייה ופתיחת כל המסכים מתפריט הנייד.
5. הגדר סוד Gemini בערוץ מאובטח ובדוק חיפוש חי ותמונה עם נתוני בדיקה ובהסכמה. שמור תוצאות אימות ללא מפתח. הצג במפורש חוסר זמינות אם השירות עדיין נכשל.
6. בצע בדיקות ממוקדות לכל שינוי, הימנע מהרחבת מערכת מיותרת, ועדכן README ואת מסמך ההעברה לפי המצב הסופי.
7. רק בסוף בדוק מחדש גישה ל־GitHub. קרא את HEAD ואת הקבצים, שמור שינויים אחרים, העבר את המקור בלי data, .env, .git או סביבת QA, ופתח commit/branch מסודר. אין force-push ואין החלפת היסטוריה. אם כתיבה עדיין מוחזרת כ־403, דווח על החסימה ואל תציג העלאה כהצלחה.
8. פרסום מחדש לאתר החי הוא שלב נפרד לאחר אישור המשתמש להפסיק עבודה מקומית. פריסה מוצלחת חייבת להיות מאומתת בתוצאת השירות. מסור קישור ודרך כניסת admin בלי לחשוף סיסמה.
